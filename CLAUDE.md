# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**City of Small Chances** — a grounded urban life game. The live experience is a full-screen, walkable 3D **Old Harbour** in Three.js: a living day/clock with deterministic weather, a wallet + energy pocket, jobs worked off a notice board, a 40-role posed crowd, and a fully procedural soundscape. ~9k lines of hand-written JavaScript (over half of it `world.js`). Public repo, MIT-licensed. (An earlier "legacy" DOM build over a raw-WebGL2 renderer, plus the deeper unused simulation engine, were **removed** — the walkable `src/three/` build is the only code path.)

The design book (`City_of_Small_Chances_Game_Design_Book.md`) is the source of truth for *intent* — pillars, numbers, the "debugging rule" (every chance must explain why it's locked/open). It is git-ignored (kept out of the public repo). Read it when a feature's *why* is unclear.

## Commands

There is **no build, no bundler, no transpiler, no package.json, no node_modules**. Pure HTML/CSS/ES-modules + a vendored Three.js r170 (`assets/vendor/three/three.module.js` — the core ESM only, resolved via the importmap in `index.html`). **No examples/jsm addons are vendored**: OrbitControls, GLTFLoader etc. don't exist here unless you vendor the file and map it. Do not introduce a build step or npm dependency without explicit instruction — "no build step" is a hard design constraint.

```sh
# Run locally — ES modules need http://, not file://. Any static server works:
python3 -m http.server 8000   # then open http://localhost:8000
```

- **Tests:** none exist. There is no test runner, no `*.test.js`, no CI. Verification is manual — by playing the build, and by headless-rendering it with Chromium (load `index.html` or a throwaway probe page, read `window.__game`, screenshot; probe logs go in the git-ignored `logs/`). `window.__game` exposes `{ scene, camera, renderer, player, world, input, CAM, day, interactions, ui, pstate, hud, audio }`, and `ui.js`/`createStatsHUD` expose test getters (`promptText`, `panelTitle`, `moneyText`, `energyPct`, `weatherFx`, …) for exactly this. If asked to "run the tests," say there are none rather than inventing a command.
- **Lint/format:** none configured (no eslint/prettier). Match the surrounding code's style by hand.
- **Deploy:** GitHub Pages serves the repo root of `master` directly (remote `Mon-ius/City-of-Small-Chances`). No `gh-pages` branch, no Actions — pushing to `master` republishes the live site. `.nojekyll` is required (ES-module paths) — never delete it. (Note: the auto-memory's `gh-pages` deploy note refers to a *different*, parallel repo — `city-of-small-chances-3d` — not this one.)

## Architecture — the one thing to understand first

There is **one front door**. `index.html` loads `src/three/main.js`; everything the player sees lives under `src/three/`, reading two data tables and the calendar:

```
                          ┌─ src/data/jobs.js   ← the notice-board jobs
src/three/  (LIVE game) ──┤─ src/data/npcs.js   ← the harbour's people (self-contained)
                          └─ src/core/time.js   ← the shared day/clock calendar
```

- **`src/three/` is the whole game.** A plain Three.js frame loop — no ECS, no framework, no second build. It keeps its **own lightweight player pocket** (money/energy + its own `jobStatus`/`work` gating) in `src/three/playerstate.js`.
- **`data/jobs.js`, `data/npcs.js`** are declarative content tables; **`src/core/time.js`** is the calendar. That is the entire non-`three/` surface.
- **What used to be here and is gone:** a parallel "legacy" DOM build (`src/main.js` + `src/ui/` + `src/render/`) and the deeper simulation engine (`core/{state,store,game,save,rng}.js` + `src/systems/` + `data/{districts,content,opportunities}.js`). If you find a reference to any of them, it is stale — remove it. Known stragglers: `styles/main.css` (724 dead lines, referenced by nothing), "retained engine" header comments in `main.js`/`daycycle.js`, and README's "retained engine" copy. The data files' own header comments also describe the deleted engine's richer interpretation — **trust the code that reads them, not the headers**.
- **No persistence, no network.** The only client storage in the whole game is audio's `localStorage` mute flag (`cosc.muted`); money, energy, day and clock reset on reload, and nothing fetches. There is no save system to wire into — a "save the game" task starts from zero.
- **Determinism is a project rule:** `grep Math.random src/` hits only `audio.js` (noise synthesis — the one deliberate exception). World/crowd variation is seed- or hash-derived so headless screenshots stay byte-stable; the weather is a fixed 6-day cycle keyed off the day counter, explicitly no RNG.

**Practical consequence:** there is only one layer. A gameplay change lives in `src/three/` (+ the two data tables it reads). If you want a deeper simulation, build it inside the `three/` slice.

## The live game (`src/three/`)

`main.js` owns the loop and the boot.

- `main.js` — boot (WebGL renderer, scene, player, day cycle, audio) and per-frame `tick()`: drains input, moves the player (camera-relative, XZ-only, clamped to the `world.bounds` AABB — no other collision), animates every world array (citizens, `locals` turning to face a near player, billboards, clouds, Lissajous-flying gulls, smoke plumes, critters/washing/flags), advances the clock, and re-scores the open interaction panel when the minute ticks over. Also owns the **deterministic 6-day weather cycle** (audiovisual only — gates nothing) and the day-rollover watch that fires the transition veil and swaps weather.
- `world.js` — **one export, `buildWorld(scene)`**; everything else (~70 prop builders, `surfaceMaterial(object, repeat, extra, prefix)`, `propMaterial`, `windowAtlasMaterial()`, `windowPlane(winW, winH, cell, material)`) is module-private. Surfaces use **committed PBR maps** (`assets/textures/harbour/`): albedo + normal + packed ORM (Three.js reads roughness←G, metalness←B; the R/AO channel is *not* sampled — no `aoMap` is ever assigned). Returns a large **handle bag** — arrays main.js ticks per frame (`citizens`, `locals`, `billboards`, `clouds`, `soaringGulls`, `smokePlumes`, `critters`, …) and setters daycycle drives per minute (`paintSky`, `setSkyBlend`, `setOvercast`, `setMoon`, `setWindowGlow`, `setLampGlow`, `setBeacon`, …). **Adding any lit/animated thing = add an array or setter here AND wire it in `main.js` or `daycycle.js`.** The fastest map of the file's ~45 titled sections is `grep '// ──' src/three/world.js`. Placement is hand-authored coordinates; the clearance comments (occupied slots, patrol lanes, walkable bounds) are load-bearing — sweep new props against them. The repo's settled idiom: props are **real ground-planted geometry with a soft contact-shadow blob**, not billboards (only clouds/far vessels/FX halos stay billboards).
- `daycycle.js` — borrows the `src/core/time.js` calendar; advances 1.5 in-game min/real s and interpolates keyframed lighting (dawn→night) across all the world setters. Contract: `createDayCycle(world, scene, {startMin, minutesPerSecond})` → `{ minutes, day, update(dt), setMinutes(m), label() }`. **`minutes` is a continuous float** — `Math.floor` it before formatting or comparing. `setMinutes` clamps to the day (a worked shift pins just before midnight); only `update()`'s wrap rolls `day` and lands at 06:00. Sky repaints are throttled to once per in-game minute; sun/lamps/fog are per-frame.
- `player.js` — the **figure builder + pose library** shared by the player and every NPC. Since spr-093 the body is a modeled procedural humanoid: tapered two-segment limbs with joint bulges, modeled hands and shoes, a face — still capsule/sphere primitives, no skinned mesh. Contract: `createFigure(look, opts)` where `look` is `"player"`, a `PALETTES` key, one of ~44 `LOOKS` role keys (incl. named `Mei`/`Tomo`/`Jun`/`Rafiq`), or a raw look object; returns `{ root, update(dt, speed), body, headPivot, legL/legR/armL/armR }`. **`fig.body` is load-bearing** — world.js parents pose props (rod, basket, cane…) to it. `opts` carries `seed`, `castShadow`, `noProp`, and **~29 mutually-exclusive pose flags** (`seated`, `leaning`, `casting`, `bowing`, `caning`, …): `update()` is a dispatcher of early-return branches, each owning the skeleton for a frame. **Adding a pose = new opt flag + new early-return branch + one world.js call site.** Rig invariants every pose respects: no articulated elbows/knees; limbs hang at fixed HIP_Y/SHOULDER_Y with "top at y=0, tip at y=−length" (spr-093 preserved this so all pose math survived); a pose holding a body-parented prop must keep the trunk near-still or the prop visibly floats. Seed convention: `seed 0` = the hero gait (player + patrol walkers, byte-identical); `seed > 0` = a deterministic idler (stance, breath/gaze phases, fidgets). The player alone is dressed in codex PBR character maps (`assets/textures/player/CHAR_Player_*`) via `playerSkin()` with flat-palette fallback; the crowd stays palette-coloured so the hero reads apart.
- `audio.js` — **fully procedural Web Audio; zero audio files ship** (`assets/audio/` is intentionally empty). `createAudio()` → `{ resume, update(dt, speed), setTimeOfDay, workShift(family), panelOpen/panelClose, confirm/deny, pay, toggleMute, … }` — an ambient bed (sea, wind, gulls, night lamp hum, a time-of-day-shaded music pad) under one-shot SFX (footsteps by distance walked, per-job-family shift montages, UI cues). The context starts suspended and resumes on first gesture; if Web Audio is missing a **silent no-op stub** is returned, so callers never guard. Mute persists in `localStorage['cosc.muted']` and toggles via the HUD button or the M key (a raw listener in main.js, outside input.js).
- `playerstate.js` — the player's **pocket**: money ($240 start — the design book's carried debt), energy (100), the per-family energy-cost formula, `jobStatus()` and `work()`. `jobStatus` gates on **four** reasons — `closed` (window), `requires`, `no-time` (shift must finish by `DAY_END_MIN`), `tired` — and adapts the pocket through `simState()` → `{condition:{energy}, inventory, skills}` before calling `job.requires(...)`. The pocket never grows `inventory`/`skills`, so `courier_run` and `civic_filing` are **permanently locked by design**. `work()` reads only `family, minutes, windows, requires, pay.base` from a job — the rest of the job shape is authored-ahead and unread.
- `input.js` — held keys (WASD/arrows) vs. **edge-triggered one-shot actions** (E, Esc, digits → `'pick:N'`), plus pointer-drag camera yaw/pitch. `takeAction()` pops one action per frame; drag is consumed every frame even while a panel is open. Window blur clears held keys.
- `interactions.js` — `INTERACTABLES` (vendor stall, notice board), the proximity test, and the panel builders. `boardBuild()` scores every job against the live clock + pocket; `boardAct()` calls `pstate.work()` then `day.setMinutes(...)`, and returns `{ ...res, family }` **on purpose** — main.js uses `family` to pick the shift audio + HUD montage; new `act()` handlers should follow. world.js imports `INTERACTABLES` to place the floating markers — **moving an interactable means updating both files**. Asset-path contracts live here: portraits resolve from `npc.short` (`CHAR_Portrait_<Name>_<tier>_albedo.png`, tier hardcoded `stranger`), job emblems from `job.id` (`UI_Icon_Job_<id>.png`) — renaming either orphans committed art.
- `ui.js` — the DOM overlay: context `[E]` pill, interaction panel, money/energy HUD with mute button, **plus four full-screen FX overlays** — condition vignettes + state badge (low-energy/burnout/well-rested thresholds live here, *separate* from playerstate's gates and jobs' floors — changing one does not change the others), the day-transition veil (`playDayTransition()`, deliberately masks the relight pop + weather swap), the weather layer (`setWeather(rain, fog)`), and the per-family shift montage (`playShiftScene(family)`). Timed FX use a generation-token pattern to cancel stale timeouts, and reduced-motion is handled in JS here (CSS handles it elsewhere — don't add competing CSS transitions). The clock line is **not** here: `#hud` is static markup in `index.html`, updated by main.js.

**Idioms here:** `build(ctx)` panels are live-built on open and re-built each minute — but note the static vendor panel is built **once at module load**, only `build`-based panels are live; `build` receives `{ nowMin, pstate }` while only `act` gets `{ nowMin, pstate, day }`; `nowMin` is the **fractional** live clock — floor before exact comparisons (integer minutes hold only in the data tables and playerstate gates).

## The calendar (`src/core/time.js`)

The shared day/clock: `DAY_START_MIN=360`/06:00, `DAY_END_MIN=1440`/24:00, named `BLOCKS`, `fmtClock` (wraps mod 1440 — minute 1440 renders `00:00`), `blockFor` (returns "Late night" for any out-of-range minute). The live build imports **only** `fmtClock`, `blockFor`, `DAY_START_MIN`, `DAY_END_MIN` — `advanceClock`, `minutesLeft`, `WEEKDAYS` are dead exports left from the engine (and `advanceClock`'s clamp semantics differ from daycycle's wrap; don't model new code on them).

## Data tables (`src/data/`) — where content is authored

Declarative only; the `three/` layer interprets them — and reads a much thinner subset than the tables author (the rest is authored-ahead for future systems, not dead). To add content, copy an existing entry and adjust:

- `jobs.js` — `JOBS`: `id, name, family, district, windows [[fromMin,toMin]], minutes, requires(state), requiresNote, pay{...}, task{...}, risk, mastery`. Ids: `market_haul`, `harbour_labour`, `dock_load`, `courier_run`, `civic_filing`. Live-read fields: `pay.base`, `family` (doubles as the energy-rate key), `minutes`, `windows` (edges inclusive), `requires` + `requiresNote` (surfaced verbatim on locked rows). `district` is **not** enforced — all jobs post to the one harbour board. A new job's `requires` must stick to the `{condition, inventory, skills}` shape or extend `simState()`.
- `npcs.js` — `NPCS`: `id, name, short, role, icon, color` (US spelling — `colour` gets undefined), `blurb, pressure, schedule` (ordered segments `{to, district, where, at}`, not per-hour), voice lines per tier, `favour`. Ids: `mei`, `jun`, `rafiq`, `tomo`, `clara`, `ava`. Only **mei**'s card is consumed live (the vendor panel, always at "stranger"); voice has 3 tiers while `STAGES` defines 5 — a future relationship system must map them. Carries its own local `clamp`.

**Watch out:** a window that wraps past midnight (`[[22*60, 2*60]]`) is **not** supported. Money has no clamp (only condition meters do). Named-NPC identity is duplicated in **four** uncoordinated places — the `npcs.js` card, `player.js` LOOKS/ROLE_* rows keyed by capitalized name, the `world.js` placement call, and the portrait filename from `npc.short`; renaming an NPC means touching all four.

## Conventions

- **Commits:** Conventional-Commits prefix + a poetic, em-dashed milestone phrase, e.g. `feat(game): an honest day's work — wallet, energy & working a shift off the board`. Do not add `Co-Authored-By` trailers.
- **Releases:** milestones are tags `v0.X.Y` whose narrative names (`v0.1.3 — An honest day's work`) live in the README roadmap, updated with the tag. The cadence has lapsed: `master` (and therefore the live site) is ~200 commits past the `v0.1.3` tag — the whole spr-031…spr-094 sprint (audio, weather, crowd, poses, modeled humanoid) is live but untagged. Recent tags are lightweight; earlier ones annotated.
- **Art assets (intentional pivot):** ~64 MB of committed painted art, generated with codex's `image_gen` skill (GPT-Image-2) and post-processed locally — ImageMagick for the seamless PBR surface maps (`assets/textures/<district>/`, 512² powers-of-two), Pillow + codex's `remove_chroma_key.py` for the larger share: cutout sprites (`assets/sprites/` — props, citizens, sky, FX, signage; longest-side-512, arbitrary aspect) and UI art (`assets/ui/` — portraits, icons, panels, shift scenes). Naming contract: `Category_District_Object[_Variant]_<map>.png`, Category ∈ ENV/PROP/CHAR/UI/FX. The per-batch pipeline lives in `tools/gen/` (launch + self-validating postprocess scripts; briefs in `docs/BRIEF_batch*.md`; plan/manifest in `docs/ART_PLAN.md` + `docs/ASSET_MANIFEST.md` — the manifest is stale for batches 59–70). Raw generation sources (~630 MB under `tools/gen/source_*`) are **git-ignored — never commit them**; assets are **curated, not byte-regenerable** — commit the chosen PNGs. **No `npm install`, no new deps** for the toolchain. Only `harbour/` and `player/` textures are wired; the other 12 district dirs are **ship-ready staged art for future walkable districts — not dead code, do not "clean them up"**.
- **No scrollbar, ever:** the game is full-screen; `styles/game.css` locks the viewport, and the HUD overlay is `pointer-events:none`. Two deliberate exceptions/contracts inside that rule: the interaction panel's *inner* content may scroll (`.panel__scroll` — don't "fix" it), and the HUD z-index stack in `game.css` is semantic (vignettes < weather < veil < stats < prompt < boot < panel < montage) — reordering breaks visible masking.
- **`index.html` is a contract, not boilerplate:** main.js hard-requires `<canvas id="game">`, and the `#boot` splash stays opaque until something adds class `gone`. The `og:` social-card URLs are absolute (renaming the repo breaks them), and the `[1–5] to pick` hint is hand-synced to the five-job count (input.js already accepts 1–9).
